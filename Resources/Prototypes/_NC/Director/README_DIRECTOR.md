# Документация системы «Живого Мира» (Global Director System)

Система **Global Director** — это автономный «рассказчик», который управляет динамическими сценариями. События теперь не просто случаются, а развиваются как нелинейные истории (State Machine), реагируя на мир и игроков.

---

## 1. Глобальный Конфигуратор (Мозг Директора)
Файл: `Resources/Prototypes/_NC/Director/gamerule.yml`

```yaml
- type: entity                 # Объявление новой сущности
  id: GlobalDirector           # Уникальный ID для системы (используется в коде)
  parent: BaseGameRule         # Наследование базовой логики игровых правил
  components:                  # Список компонентов, прикрепленных к этой сущности
  - type: GlobalDirector       # Логический компонент Директора
    minDelay: 300              # Минимальное время покоя между событиями (в секундах)
    maxDelay: 600              # Максимальное время покоя между событиями (в секундах)
    defaultAnnouncerId: "Director" # Имя отправителя в чате (по умолчанию "Глобальный Директор")
    announcementColor: "#00ffff"   # Цвет текста объявлений Директора (Cyan)
```

## 2. Описание Сценария (DirectorEvent)
Файл: `Resources/Prototypes/_NC/Director/*.yml`

### Заголовок события (Header)
```yaml
- type: directorEvent          # Указываем тип прототипа (наше новое событие)
  id: TestEvent                # ID для спавна через консоль (startdirectorevent TestEvent)
  name: "Тестовое событие"      # Понятное название для логов и админ-панели
  weight: 10                   # Шанс выпадения (чем выше число, тем чаще выбирается Директором)
  announcerId: "Arasaka"       # Переопределение имени диктора для этого конкретного сценария
  announcementColor: "red"     # Переопределение цвета текста для этого конкретного сценария
  startPhase: "Initial"        # ID фазы, с которой всегда начинается этот сценарий
```

### Структура Фазы (Phases)
Каждая фаза — это отдельный «слой» истории.

```yaml
  phases:                      # Начало словаря всех фаз
    Initial:                   # Уникальный ID текущей фазы
      name: "Подготовка"       # Название фазы для отладки
      duration: 300            # Таймер жизни фазы в секундах (авто-переход после этого времени)
      announcement: "msg-id"   # ID строки из .ftl файла (выводится в чат в начале фазы)
      locationTag: "Hidden"    # Искать на карте точки DirectorSpawnPoint с этим тегом
      aiDomain: "Tactical"     # Установить этот HTN-домен всем ботам события в этой фазе
      cleanup: false           # Если true, все сущности фазы удалятся ПРИ ВЫХОДЕ из неё
      spawns:                  # Список сущностей, появляющихся в начале фазы
        - MobHuman             # ID прототипа NPC 1
        - MobHuman             # ID прототипа NPC 2
      triggers:                # Список условий для МГНОВЕННОГО перехода дальше
        - type: MobKilled      # Тип триггера: смерть заспавненного NPC
          target: MobHuman     # (Опционально) Считать смерти только этого прототипа
          count: 2             # Нужно именно 2 смерти, чтобы триггер сработал
      nextPhases:              # Куда Директор может пойти после завершения этой фазы
        Combat: 70             # Перейти в фазу 'Combat' с вероятностью 70%
        Police: 30             # Перейти в фазу 'Police' с вероятностью 30%
```

---

## 3. Типы Триггеров (Triggers)

Триггеры позволяют событию быть динамичным:
*   `type: MobKilled` — Смерть NPC, созданного этим событием. Параметр `count` задает порог.
*   `type: EntityDestroyed` — Уничтожение объекта (турели, ящика, маркера).
*   `Timer` — Всегда работает неявно через параметр `duration`.

---

## 4. Пространственная привязка (Mapping)

Чтобы NPC не появлялись в стенах или космосе:
1. Маппер ставит сущность `DirectorSpawnPoint`.
2. В компоненте `DirectorSpawnPoint` пишет `locationTag: "MyTag"`.
3. В YAML события пишет `locationTag: "MyTag"`.
4. Директор найдет эти точки и выберет одну случайную для высадки группы.

**Совет:** Используйте теги `Maintenance`, `Alley`, `Rooftop` для создания логичных точек появления.

---

## 6. Команды управления

*   `startdirectorevent <ID>` — Принудительный старт (игнорирует глобальный таймер).
*   `advancedirectorevent <UID>` — Силовой переход к следующей случайной фазе.
*   `canceldirectorevent <UID>` — Жесткая остановка и удаление всех объектов события.
